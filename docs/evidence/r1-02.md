## 配置与验证

设置页保存一套端点和 API 密钥，密钥只写服务端 `AGENTANYWHERE_DATA_DIR/model-connection.json`，默认目录是项目下 `data/`；文件模式 0600。部署时将 `AGENTANYWHERE_DATA_DIR=/data` 指向 bun 用户可写的持久卷。页面仅接收 `hasCredential`，不会回显密钥；更换端点主机要求重新填写密钥。端点或密钥变化时，原目录及其来源保留并标为过期，须重新刷新；已选模型与默认模型保留。刷新只请求配置端点的 `/models`，不跟随重定向。刷新失败保留上次有效列表、已选模型与默认模型。网关 401 作为应用 502 返回，避免与登录过期 401 混淆。保存连接及刷新目录不会覆盖页面尚未保存的模型编辑；请求期间设置控件暂时禁用。

本地黑盒回归使用真实 Web/API、服务端文件和进程重启，仅替换外部网关 HTTP 响应。验证登录边界、保存、网关发现、401/空列表/超时、失败保留、端点更换保护、密钥不回显、文件权限和重启恢复。`bun run build && bun run typecheck && bun test` 首轮通过：5 项测试、61 个断言。复核后的连接身份变更回归单文件通过，构建与类型检查通过。

主会话用 ego-browser TaskSpace 31 检查 `localhost:19110` 的真实应用与独立文件存储；仅外部模型列表由 `localhost:19111` 提供可控响应。浏览器完成：保存连接后密钥框清空、不回显；刷新取得两个模型；搜索 `astra` 只显示匹配项；选择 `gpt-6-astra`、填写人工参数、设置 Responses 和默认模型，保存并刷新页面后仍在；手填 `manual-fixture` 模型并保存。模拟网关 401 后，页面以中文提示且未跳登录；刷新页面后错误状态、旧模型及默认模型仍在，密钥框保持空白。截图：`/tmp/agentanywhere-r1-model-settings.png`。
