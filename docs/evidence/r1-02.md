# R1-02 模型连接与发现

## 网关契约

2026-09-18 对当前 sub2api 网关执行脱敏 `GET /v1/models`：HTTP 200，返回 24 个模型。每项观察到 `id`、`display_name`、`owned_by`、`created`、`object`、`type`；例如 `gpt-6-astra` 的 `owned_by` 为 `openai`。未观察到上下文长度、输出上限、输入模态、工具、推理、协议或价格字段。sub2api 运行版本尚未确认。列表可见只证明网关列出该 ID，不能证明模型调用、协议或能力。

应用保存网关的 ID、展示名、所有者、类型和创建时间，供后续精确目录映射使用。当前必要 Pi 运行参数（上下文长度、输出上限、输入模态、推理能力）由用户人工填写；工具能力与参考价格也可填写。未填写时显示未知；价格不以零代替未知。所有人工值标明来源。模型目录补全和实际协议调用留给后续票。

## 配置与验证

设置页保存一套端点和 API 密钥，密钥只写服务端 `AGENTANYWHERE_DATA_DIR/model-connection.json`，默认目录是项目下 `data/`；文件模式 0600。部署时将 `AGENTANYWHERE_DATA_DIR=/data` 指向 bun 用户可写的持久卷。页面仅接收 `hasCredential`，不会回显密钥；更换端点主机要求重新填写密钥。刷新只请求配置端点的 `/models`，不跟随重定向。刷新失败保留上次有效列表、已选模型与默认模型。网关 401 作为应用 502 返回，避免与登录过期 401 混淆。

本地黑盒回归使用真实 Web/API、服务端文件和进程重启，仅替换外部网关 HTTP 响应。验证登录边界、保存、网关发现、401/空列表/超时、失败保留、端点更换保护、密钥不回显、文件权限和重启恢复。命令：`bun test src/model-connection.test.ts`、`bun run typecheck`、`bun run build`。真实浏览器操作证据由主会话使用同一 ego-browser TaskSpace 31 补充。

本票未验证实际模型推断、Chat Completions/Responses 流式调用、工具往返、usage、价格准确性或 models.dev 自动补全；这些由后续执行与元信息票验收。
