# R1-04 工作创建与待执行请求

所有者可在工作页填写目标或公开链接，选已配置模型，并在高级选项中覆盖协议。`POST /api/tasks` 使用客户端 `requestId` 去重；创建一个 Task、一个工作 Thread、初始用户消息和一个待执行 Run。工作列表与详情均从 PostgreSQL 读取，刷新或服务重启后可恢复。

Run 的模型快照来自模型连接的可见有效配置，包含模型、协议、端点及已知运行参数和来源字段。Run 在数据库私有列保存凭证版本引用，模型连接的受限文件保留各版本端点和凭证；可信控制侧可按 Run ID 解析原连接，并检查端点与快照一致。公开 API、Run 模型快照均不返回引用或明文凭证。旧版 Run 若创建时未写入凭证版本引用，不能追溯当时的凭证，解析时明确失败。

本票使用 Bun SQL 连接 `DATABASE_URL`，启动时建立 `work_tasks`、`work_threads`、`work_runs`、`work_messages` 四张表。工作目前只进入 `queued`，界面显示“待执行”；Worker、队列消费、模型调用、实时输出与后续状态流转均待后续票验证。

本地公开 API 回归使用独立 PostgreSQL 的临时 schema，验证了鉴权、跨域拒绝、参数错误、目标与仅链接创建、重复请求去重、详情和列表、服务重启恢复，以及端点和凭证轮换后旧 Run 解析原连接、新 Run 解析新连接。详情与设置 GET 不泄露凭证。旧格式模型连接文件在启动时迁移为凭证版本，重启后仍可解析；文件权限为 0600。`bun run build`、`bun run typecheck`、完整 `bun test` 均通过（7 pass）。Docker 镜像构建通过，非 root 容器连接测试库后验证登录 204、工作列表 200、模型设置 200、创建工作 201 且响应不含凭证；临时容器、镜像、数据与 schema 已清理。

真实浏览器 TaskSpace31/p1 验收发现首页曾因 `useState(crypto.randomUUID)` 脱离 `crypto` 调用而崩溃，改为显式箭头调用后重载正常。空目标与链接提交显示校验错误；主题加公开链接创建时高级选项覆盖为 Chat Completions，详情显示固定协议、初始消息和“待执行”，刷新后保留；仅公开链接创建沿用模型默认 Responses，返回列表显示两项待执行。Worker 尚未接通，未验证真实模型请求。
