## 正式备份、发布与回退

发布窗口先后在 Web/queue 停止前后检查正式 Work Run 与 Steward 轮次均为 0。私有备份 `/opt/agentanywhere/backups/20260920-r3-release` 包含 PostgreSQL custom dump 与同窗口的完整 `runtime/` tar，并记录 R2 发布 SHA、三类正式镜像和旧 Compose/deploy。四个隔离验收 schema 明确从 dump 排除；`pg_restore --list`、`tar -tf` 和 `sha256sum -c` 均通过。随后只复制 4aa 的正式 Compose/deploy，并只重建 Web 与 queue。Web 健康、queue 运行且镜像标签为 4aa；PostgreSQL、OpenSandbox、SearXNG 的容器 ID 与启动时间未变化。

发布脚本在正式写入前暴露两项错误，均由保护关卡拦截：

- 首轮 guard 错误要求正式容器必须设置一次 `QUEUE_SCHEMA`；实际 `src/queue-worker.mjs:18` 在变量缺失时使用 `pgboss`。该轮在停服前退出，正式仍运行 R2，未创建备份。
- 第二轮把 `pg_dump --file=-` 当成标准输出；PostgreSQL 18.6 实际在容器根目录写入字面文件 `/-`，宿主重定向得到 0 字节 dump。`pg_restore --list` 拒绝该文件，发布尚未开始，失败处理恢复 R2 Web/queue且没有恢复或改写数据库。删除该临时文件并改用 `pg_dump` 默认标准输出后，配对备份校验和 4aa 部署通过。

这些失败说明备份可读性检查和 Web/queue 回退实际生效；失败备份未被当作可用恢复点。
