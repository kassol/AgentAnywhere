2026-09-18，cc-la 隔离 `19112/19113` 栈以 `r1-integration-83a86be` 镜像运行 `node infra/r1/test-recovery.mjs`。真实 PostgreSQL、pg-boss、Pi 与 OpenSandbox 链路通过：短暂模型故障后原 Run 继续，已完成的 `echo_observation` 只出现一次；持续故障保留失败检查点，手动重试创建新 Run，未重复原工具；queue 在模型挂起时重启，旧 Run `3e612211-27ca-4aa1-bad8-0684e660f5ea` 成为 `lost/cleaned`，新 Run `26117208-acaf-4593-ac01-7e8aded5cda4` 从检查点完成，原 epoch 的工具事件只有一次、新 Run 无重复工具。40 次模型调用上限分别验证明确选择继续后 epoch 2 完成，以及明确选择结束后 `cancelled/cleaned`。脚本对各 Run 使用 OpenSandbox SDK 检查无活沙箱。45 分钟边界由 `src/work.test.ts` 的服务端测试时钟与真实 PostgreSQL 验证；本次远端脚本未等待 45 分钟。

首次真实重试曾暴露 `retryTask` 的 JSONB 参数编码：`checkpoint_ref`、`model_snapshot`、`context_snapshot` 被存成 JSONB 字符串，新 Run 无法解析检查点。真实 PostgreSQL 回归先断言三字段为对象得到红灯，再在 INSERT 参数转成 text 后显式 `::jsonb`，同一断言转绿；重新运行的远端重试路径通过。

该测试先发现旧版停止流程会使 Pi 所在容器退出：execd 的停止命令收到 `CommandExecError: -1 / signal: terminated`，旧 Run `a313c5ab-bb56-454f-ac69-ff57e64b82ec` 进入 `save_failed/blocked`，SDK 显示沙箱 `Terminated`。尝试从已退出容器复制 `checkpoint.jsonl` 返回文件不存在，未取得可恢复检查点；在 SDK kill 确认无活沙箱后，仅将该隔离测试 Run 精确标为人工清场的 `lost/cleaned`。这次失败不计正常恢复通过。修复后 Pi 在收到恢复停止信号时先 abort、等待执行 Promise 结束，再原子写入 idle 标记并保持进程与 execd 可读；queue 只在看到 idle 后复制检查点，超时保留 `blocked`。上述重新运行的真实脚本通过。
