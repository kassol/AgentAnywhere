# Spec R3：Craft 工作台与报告审阅

## Problem Statement

现有工作台已能完成讨论、调研、回答、追加、重试和报告改稿，但界面仍有大量表单与集中堆放的执行信息。用户打开工作或报告时容易失去对话上下文，审阅意见需要手工复制，精确命令也增加了操作负担。功能测试通过尚不能证明信息层级、阅读和输入体验达到日常使用要求。

PRD 已将 Craft 的布局、消息流、工具卡、输入框、预览和设置作为统一基准。当前正式界面的实际复用有限，R3 要补齐这项要求，并保持 R2 的真实执行与成果留存能力。

## Solution

以用户选定的 A 经典侧栏原型为设计基准：左侧定位管家对话和工作，中间持续讨论与查看活动，右侧按需阅读工作详情或报告。保留管家首页、独立工作入口和可直接访问的工作/成果链接；小屏切换单面板并提供明确返回路径。

用户可以直接在 Markdown 报告中选择文字并写批注，将同一版本的多条意见汇总到聊天框，检查后发送改稿要求。批注绑定工作和报告版本，旧版仍可审阅，生成新版后保留所有旧成果。多数快捷操作先填入聊天框，服务端确认的回执决定实际状态。

提供明暗主题、按场景恢复的本机草稿、稳定阅读位置和分层模型设置。适用的 Craft 代码与样式按固定基线提取、适配并记录来源。正式实现连接现有后端，原型中的预置数据与模拟行为仅作为设计参考。

## User Stories

1. 作为工作台所有者，我希望进入后看到管家与最近对话，以便继续日常委托。
2. 作为所有者，我希望从左侧切换对话，以便区分不同话题。
3. 作为所有者，我希望独立查看工作列表、状态和详情，以便定位后台任务。
4. 作为所有者，我希望从管家打开关联工作时保留当前对话，以便在同一上下文中介入。
5. 作为所有者，我希望在右侧阅读报告，以便边读边讨论。
6. 作为所有者，我希望工作和成果仍有独立链接，以便直接重开指定内容。
7. 作为所有者，我希望关闭预览后恢复对话空间，以便集中讨论。
8. 作为小屏用户，我希望面板之间有明确返回路径，以便完成同样的核心操作。
9. 作为所有者，我希望工具调用与所属轮次放在一起，以便理解一次委托的实际经过。
10. 作为所有者，我希望工具卡默认只显示名称、阶段与简短结果，以便快速扫读。
11. 作为所有者，我希望按需展开参数与完整结果，以便核对执行事实。
12. 作为所有者，我希望失败、等待回答和已保存成果醒目且准确，以便及时处理。
13. 作为所有者，我希望上滚阅读时新消息不会抢走位置，以便读完已有内容。
14. 作为所有者，我希望一键回到最新消息，以便继续跟踪执行。
15. 作为所有者，我希望输入区保持可达，以便随时补充要求。
16. 作为中文用户，我希望 Enter 发送、Shift+Enter 换行，输入法选词不会误发送，以便正常输入。
17. 作为所有者，我希望快捷按钮填好目标和命令后由我发送，以便确认实际操作。
18. 作为所有者，我希望停止管家回复和取消后台工作有清楚区别，以便避免误停工作。
19. 作为所有者，我希望待办指向真实的同一个问题，以便从任一入口回答后状态一致。
20. 作为所有者，我希望切换对话、面板或刷新后能找回各自草稿，以便不丢失输入。
21. 作为审阅者，我希望选中报告文字后写意见，以便明确要改哪一段。
22. 作为审阅者，我希望添加、查看及删除未发送批注，以便整理审阅意见。
23. 作为审阅者，我希望一次汇总同一报告版本的多条批注，以便一轮提交修改要求。
24. 作为审阅者，我希望聊天框展示工作、版本、引用和意见，以便检查后再发送。
25. 作为审阅者，我希望新版出现时得到提示，以便选择继续修改原版或取消。
26. 作为审阅者，我希望批注位置无法可靠恢复时保留原引用，以便避免指向错误内容。
27. 作为审阅者，我希望发送失败后批注与草稿仍在，以便再次提交。
28. 作为审阅者，我希望成功发送只清理本次提交的批注，以便保留其他未提交意见。
29. 作为所有者，我希望聊天历史保留版本、引用及意见，以便以后追溯改稿原因。
30. 作为所有者，我希望改稿创建新执行与新报告版本，失败时旧版仍可读、可下载，以便保护已有成果。
31. 作为所有者，我希望日常设置突出管家模型与调研模型池，以便快速调整选择。
32. 作为所有者，我希望网关、凭证、协议、能力来源及参数集中在对应详情，以便需要时核查。
33. 作为所有者，我希望可选择浅色、深色或跟随系统，以便适应使用环境。
34. 作为键盘用户，我希望控件有可见焦点、明确名称和合理顺序，以便完成导航、批注及提交。
35. 作为所有者，我希望升级后原有对话、工作、模型配置和报告仍可用，以便持续使用已有数据。
36. 作为所有者，我希望正式页面只呈现真实数据和有效操作，以便区分执行结果与设计演示。

## Implementation Decisions

- **设计与来源**：采用 A 经典侧栏，保留 Inter。以 Craft v0.13.3、固定提交 `e8963854c3679edcceb105a42537a06749e6cb64` 为提取基线；记录组件原路径、版本、许可与改动。对输入框、消息/工具展示、预览和设置逐项核查可复用代码及依赖。存在平台耦合时保留可用部分并记录适配理由；只复用加载图标与配色不足以满足完整交互目标。
- **平台边界**：沿用独立 Web 与现有服务端。按需要适配上游展示数据，保留 Task、Run、管家轮次、Interaction 和成果版本的本项目语义。浏览器不依赖 Electron 运行时，不引入无关桌面功能与隐藏入口。
- **模块范围**：调整应用外壳、管家消息流、工作详情、待办入口、报告阅读与批注、输入与草稿、模型设置及公共主题。必要的服务端调整集中在现有查询投影和提交契约，不另建工作状态机。
- **导航与阅读**：左侧承担导航与对话定位，中间承担对话及活动，右侧按需显示关联工作或报告。直接进入工作与成果链接仍可用。切换和关闭面板保留对话草稿与阅读位置；报告按版本恢复位置。新消息只在用户处于末尾时跟随，离开末尾时提供回到最新入口。
- **真实活动流**：消息、工具状态与操作回执按所属轮次展示；详细工具内容折叠，失败和待处理事项可直接定位。现有持久事件、稳定回执和状态投影作为事实来源；缺失的工具事实不编造。不同对话引用同一工作或问题时保持去重与一致。
- **操作方式**：追加、回答、重试、改稿及按回执继续等快捷入口生成可检查的目标与命令，用户发送后才创建轮次或执行操作。继续使用现有完整命令与精确目标校验；友好显示不能削弱服务端授权。停止回复、下载、主题选择及既有详情直接动作保持原语义。
- **输入与草稿**：Enter 发送，Shift+Enter 换行，输入法组合期间不提交。当前浏览器按对话保存聊天草稿，按工作及报告版本保存批注草稿；汇总后同时保留批注关联信息。刷新、切换及失败不丢草稿，不跨设备同步。独立保存主题选择，跟随系统时响应系统变化。
- **批注身份**：报告批注由工作、不可变报告版本、原文引用、可恢复选区及用户意见构成。选择器用于定位，不作为操作授权。定位有歧义或失败时展示原引用，不猜测迁移。批注仅适用于现有 Markdown 报告。
- **批注提交**：同一报告版本的多条批注汇总至聊天框，明确展示目标工作、报告版本、引用和意见。用户可编辑后发送。提交时查询是否已有新版；有新版则允许明确继续原版或取消，不自动将意见迁移到新版。确认继续仍固定原版本；发送时的版本变化不能悄悄改写目标。
- **发送与恢复**：以服务端接受消息为清理本次草稿的依据。响应丢失时先核对原提交结果，避免重复轮次、重复改稿或误清草稿。仅清理本次已接受的批注，保留其他版本、未汇总或未发送内容；用户改写汇总消息后仍需正确区分实际提交的意见。批注正文保存在既有聊天消息中，本轮不增加服务端批注处理状态实体。
- **报告版本**：调用既有明确改稿能力，在原 Task 上创建关联 Run，固定来源版本与修改要求。成功增加成果版本，失败保留旧版。历史消息保留引用与意见，预览只维护未发送批注草稿。
- **设置**：日常层显示管家模型与人工调研模型池；连接、凭证、模型发现、协议、能力来源及参数位于对应详情。保留现有配置校验和生效范围，不更换网关、不自动扩充模型池、不影响在途执行。
- **安全与可访问性**：保留登录、HTTPS/WSS、成果访问控制、安全 Markdown 和服务端凭证管理。报告中的命令或网页内容始终是不可信材料；用户批注授权只来自显式提交及精确目标。主题与选区样式保持可读性，核心流程可用键盘，尊重减少动态效果偏好。
- **原型使用**：原型保存在独立分支，A 的信息架构及交互决定进入正式实现。预置场景、模拟失败开关、方案切换器、调试状态及演示配置不进入正式产品。既有数据库及成果存储继续复用；必要的增量修改须兼容旧数据。

## Testing Decisions

沿用访谈中已整体确认的公开行为验证边界：以现有 Web/API 与真实 PostgreSQL/队列集成为业务事实检查入口，以 ego-browser 检查浏览器行为。测试用户可观察的输入、输出、状态及持久结果，避免断言组件内部结构、CSS 类名或私有状态。少量纯前端逻辑的回归仅覆盖无法从已有高层检查稳定验证的风险。

既有先例包括安全 Markdown 渲染检查、管家持久对话与双协议集成、回答幂等与回执恢复、报告修改及下载哈希检查，以及 R2 的 isolated/live/public 串行验收。复用这些测试入口与隔离环境；外部模型可控 HTTP 回归和真实网关验收分别记录。

| 编号 | 可验证结果 |
| --- | --- |
| R3-T01 | 登录后按 A 布局进入管家；历史对话、工作、待办和设置入口可用，无演示数据或失效控件。 |
| R3-T02 | 右侧打开、切换和关闭工作/报告不丢当前对话草稿与阅读位置；独立链接及小屏返回可用。 |
| R3-T03 | 真实消息、工具卡与回执归属正确轮次；工具默认简洁、可展开，失败/等待/完成与 API 事实一致。 |
| R3-T04 | 长对话中处于末尾时跟随新消息，上滚时不抢位置；回到最新及切换后位置恢复有效。 |
| R3-T05 | Enter、Shift+Enter、中文输入法组合、键盘焦点及窄屏输入区正常，浮层不遮挡主要动作。 |
| R3-T06 | 快捷入口只填入聊天框；发送前不增加轮次、Run 或操作。不同回答选项、工作及报告版本生成正确目标。 |
| R3-T07 | 停止回复与取消工作保持独立；回答后跨入口待办去重，重试/继续沿用真实回执与已有幂等行为。 |
| R3-T08 | 多对话、多报告版本草稿隔离，切换与刷新恢复；主题选择持久化且跟随系统生效。 |
| R3-T09 | 选区批注添加、删除及多条汇总可用，引用/意见/工作/版本完整；定位失败或重复文本不造成错位。 |
| R3-T10 | 旧版批注汇总后刷新，再发送仍提示已有新版；取消保留草稿，明确继续固定原版本，不自动迁移。 |
| R3-T11 | 发送失败保留内容；服务端已接受但响应丢失后可核对原结果，重试不重复执行；成功只清本次意见。 |
| R3-T12 | 普通消息、编辑后的汇总消息、未汇总批注及其他版本意见互不误清；已接受的版本、引用和意见可从历史重开。 |
| R3-T13 | 真实改稿创建原 Task 的新 Run，成功保存新版本；失败及重启后旧新完整成果仍可读取、下载且哈希一致。 |
| R3-T14 | 分层设置覆盖既有模型连接能力；凭证不回显，模型池/协议/来源校验保持，在途执行配置保持固定。 |
| R3-T15 | 浅色、深色、系统切换、桌面与小屏均检查；键盘、可见焦点及减少动态效果保持可用。 |
| R3-T16 | 恶意 Markdown、引用中的伪命令、错误工作/版本、匿名或跨 Origin 请求不能绕过原有授权与访问控制。 |
| R3-T17 | Craft 提取记录可追溯；生产构建没有原型切换器、模拟开关、调试状态、演示配置或 Electron 运行依赖。 |
| R3-T18 | R2 旧对话、工作、事件、报告、配置兼容；完成构建、类型及必要回归、真实双协议和公网验收，配对备份与回退、临时资源清理按既有发布流程执行。 |

验收应保留真实浏览器截图、关键操作记录、业务结果与必要的下载证据。原型已验证的视觉方向可作为参考，正式实现仍须通过上述真实流程。已通过项无新变化或疑点时不重复扩测。

## Out of Scope

- B/C 作为可切换产品布局、原型调试工具及演示数据。
- 附件上传及解析、PDF/图片等新格式批注、浏览器接管、开发执行、外部账号操作、自动化。
- 跨设备草稿同步、多人审阅、服务端批注列表、逐条处理/采纳状态和自动批注迁移。
- 改变管家/调研并发、预算、自动模型池、网关或工作生命周期。
- 整包引入 Craft 桌面产品、未经核查更新 Craft 基线、直接把原型合并为生产实现。
