# Spec R4：Craft 原组件迁移

发布记录：[GitHub Issue #42](https://github.com/kassol/AgentAnywhere/issues/42)。

## Problem Statement

当前工作台已能完成真实讨论、调研、介入和报告改稿，但 UI 主要是参考 Craft 后的本地实现。外观优化与功能测试不能证明已复用 Craft 原组件；继续围绕这些本地实现扩展功能，会增加后续迁移和维护成本。用户要求将实际代码复用提前为当前优先事项，并覆盖全部现有页面。

## Solution

以固定 Craft 原组件源码为基础迁移现有界面，保留 A 的侧栏与面板布局、已确认字体及 AgentAnywhere 的业务能力。局部外观与交互优先沿用 Craft；现有业务语义、数据安全和草稿保护继续成立。每个界面模块都有可核查的来源与适配记录，无法复用的部分须以证据说明并由产品所有者确认例外。

先核查上游源码并跑通“输入 → 消息与工具展示 → 打开报告”的真实链路，验证依赖和数据适配，再据此确定其余页面的具体迁移方案。最终以全部页面的真实交互和源码审查共同验收。

## User Stories

1. 作为工作台所有者，我希望常用控件以 Craft 原组件为基础，以便获得一致且可持续维护的体验。
2. 作为所有者，我希望管家、工作、待办、报告和设置都纳入迁移，以便避免页面之间长期存在两套体验。
3. 作为所有者，我希望保留 A 的侧栏与面板结构，以便继续使用已熟悉的导航方式。
4. 作为所有者，我希望保留已确认字体，以便迁移后阅读体验连续。
5. 作为所有者，我希望局部细节优先沿用 Craft，以便减少仅为贴合原型而维护的改动。
6. 作为所有者，我希望切换和重开管家对话后恢复内容，以便继续原有讨论。
7. 作为所有者，我希望发送消息仍遵守 Enter、Shift+Enter 和输入法组合规则，以便准确输入中文。
8. 作为所有者，我希望草稿按对话隔离并在刷新后恢复，以便不丢失尚未发送的要求。
9. 作为所有者，我希望发送失败保留草稿，以便修正或重试。
10. 作为所有者，我希望旧请求响应不清除后来输入的内容，以便提交期间也能继续编辑。
11. 作为所有者，我希望消息、工具活动和回执保持所属轮次关系，以便理解执行经过。
12. 作为所有者，我希望工具详情可以展开并显示真实结果，以便核对执行事实。
13. 作为所有者，我希望阅读历史时新消息不抢走位置，以便连续阅读。
14. 作为所有者，我希望可以回到最新消息，以便重新跟踪执行。
15. 作为所有者，我希望工作列表和详情显示真实状态，以便找到需要介入的工作。
16. 作为所有者，我希望从对话打开工作或报告时保留当前上下文，以便边读边讨论。
17. 作为所有者，我希望已有工作和成果链接继续有效，以便重新打开历史内容。
18. 作为所有者，我希望停止管家回复与取消工作仍有明确区别，以便准确控制执行。
19. 作为所有者，我希望待办仍指向原 Interaction，以便跨入口回答后状态一致。
20. 作为所有者，我希望快捷操作保留精确目标并允许发送前检查，以便避免操作错误工作。
21. 作为所有者，我希望填入快捷命令前确认覆盖已有草稿，以便保护未发送内容。
22. 作为审阅者，我希望阅读并下载原有报告版本，以便保留历史成果。
23. 作为审阅者，我希望批注绑定明确工作和报告版本，以便改稿意见具有确定对象。
24. 作为审阅者，我希望刷新后找回未提交批注，以便继续审阅。
25. 作为审阅者，我希望引用无法可靠定位时保留原文，以便避免错误标注。
26. 作为审阅者，我希望汇总批注后检查并发送改稿要求，以便明确授权修改。
27. 作为审阅者，我希望出现新版时明确选择继续原版或取消，以便避免自动更换改稿目标。
28. 作为审阅者，我希望提交成功只清理实际接受的草稿和批注，以便保留其他编辑。
29. 作为所有者，我希望设置继续管理管家模型、调研模型池和现有连接，以便迁移后无需重新配置。
30. 作为所有者，我希望折叠设置和切换页面不误改未编辑的配置，以便保留原有协议与能力设置。
31. 作为所有者，我希望浅色、深色和跟随系统均正常，以便在不同环境阅读。
32. 作为小屏用户，我希望导航、输入、报告和返回操作都可达，以便完成同样的核心流程。
33. 作为键盘用户，我希望焦点、控件名称和操作顺序清楚，以便无需鼠标也能完成主要操作。
34. 作为所有者，我希望升级保留已有对话、工作、成果、模型配置和本机草稿，以便持续使用。
35. 作为维护者，我希望每个迁移组件有固定上游来源和本地差异记录，以便核查真实复用并评估后续更新。
36. 作为所有者，我希望无法复用的部分先列证据并由我确认，以便防止迁移再次变成自主重写。
37. 作为维护者，我希望已替代的旧实现得到清理，以便避免维护重复 UI。

## Implementation Decisions

- **决定依据**：遵循已采纳 ADR-0002。该规格收紧实际复用标准，不将历史 R3 的交互参考追认为原组件迁移完成。
- **固定来源**：沿用 Craft Agents OSS v0.13.3、提交 `e8963854c3679edcceb105a42537a06749e6cb64`。先恢复可核查的只读源码；不在本轮隐含升级基线。保留适用许可与归属声明。
- **前置验收**：全量迁移前完成组件清单、依赖核查与核心链路运行证据。当前尚无这些新证据，具体组件导出、安装方式和依赖版本保持待验证；后续任务必须声明阻塞关系，不能凭本规格推断兼容性已成立。
- **复用清单**：覆盖应用外壳、公共控件、输入、消息与工具活动、工作列表与详情、待办、预览与批注、快捷操作、设置及主题。每项记录上游原路径与提交、本地对应模块、保留源码、适配差异、依赖和验收证据。区分原源码适配、业务专用组合和经确认的重写例外，不能以引用上游名字或配色证明复用。
- **例外处理**：有对应组件时优先保留原源码；无法复用时给出具体耦合证据与替代方案，由产品所有者确认。无直接对应的业务界面也需记录核查范围与组合方案；不得暗中以成本为由重写。未确认的例外阻塞受影响部分，独立部分可以继续。
- **布局与样式**：保留 A 的侧栏、对话与按需预览结构及已确认字体。局部样式与交互优先 Craft；发生数据保护、可访问性或业务语义冲突时保留产品契约并记录适配。字体需实际加载，中文使用既有系统回退。
- **依赖与平台**：允许引入经源码核查确认必需的 UI 依赖；不预设零新增依赖，不预先承诺引入某个依赖全集。浏览器继续独立运行，不引入 Electron 运行时、虚假的桌面 API 空实现或无效功能入口。
- **业务接口**：沿用现有公开 API 和持久化对象，在组件实际需要的位置适配展示数据与操作回调。Task、Run、Thread、Interaction、Operation 和 Artifact/Version 的身份与状态继续以本项目服务端事实为准，不迁入 Craft 的业务状态机。不计划数据库结构或对外 API 变更。
- **输入与活动**：保留草稿隔离、输入法保护、发送身份、失败重试及旧响应保护；保留轮次归属、活动折叠、真实状态和阅读位置。Craft 原组件中的额外产品能力不会仅因代码存在而向用户开放。
- **报告与介入**：保留不可变版本选择、历史下载、批注草稿、引用失效处理、新版提示和精确改稿授权。快捷入口保留现有直接动作或填入后发送的语义，停止回复与取消工作分别处理。
- **设置与安全**：保留现有单连接、人工调研模型池、协议与能力配置及在途执行快照语义。登录、凭证不回显、成果访问控制、安全 Markdown、HTTPS/WSS 与来源检查继续成立。
- **迁移与清理**：分模块替换，最终覆盖全部现有页面。保留现有数据、链接和本机草稿兼容；若需改变草稿格式，提供可验证的兼容读取或迁移。替换完成后清理本轮产生的重复实现与孤儿样式，不扩展为无关重构。
- **交付部署**：沿用项目既有部署流程与指定环境，保留备份和回滚能力；整理本轮产生的源码、构建和验证临时产物，不操作无关服务或数据。

## Testing Decisions

测试入口已由产品所有者确认：沿用公开 API/数据库集成检查与现有草稿、版本行为回归，以 ego-browser 验证完整用户流程，另行审查上游源码与适配差异。优先从用户可观察行为验证，避免将内部组件树、私有函数或截图相似度作为验收契约。

1. **核心链路前置检查**：迁入真实上游组件，在浏览器连接现有服务端，完成输入、消息与工具展示、打开真实报告；构建通过或模拟展示不构成链路完成。记录必要依赖与实际平台适配结果。
2. **现有回归复用**：参考已有输入提交与草稿、报告版本锁定、批注清理、快捷目标与模型设置检查。迁移后保持这些外部行为，仅在实现替换导致旧测试绑定内部结构时调整测试入口；不靠删除行为断言让检查通过。
3. **业务集成检查**：沿用真实 PostgreSQL、公开 API 和既有隔离执行检查，验证回答、追加、取消、重试、回执恢复及改稿未改变身份、幂等和成果留存。独立测试库缺失必须明确失败。按受影响契约选择检查，完成项目要求的构建、类型和测试门槛。
4. **全部页面浏览器验收**：覆盖管家、工作、待办、报告、设置，包含空态、有历史数据、长标题/长消息、执行中、失败和等待回答状态。验证主题、键盘、焦点、小屏导航及输入可达；使用真实数据或明确隔离的测试数据，不把演示状态当作正式能力。
5. **高风险交互**：实际执行中文输入法、换行与发送、刷新恢复、流式阅读保持、快捷命令覆盖确认的确认/取消分支、批注选择与恢复、新版确认、失败后保留编辑和成功后精确清理。自动化工具无法完成的分支明确列为未验证，不计为通过。
6. **来源审查**：逐项对照固定上游源码、本地导入和运行路径，确认迁入代码实际参与渲染与交互；审查适配差异、许可、例外决定及已替代实现的清理。死代码或未使用依赖不计入复用成果。
7. **视觉与上线证据**：在可比较视口记录全部主要页面的浅深主题和小屏证据；核查字体实际加载与布局。沿用公网登录、资源、字体策略、HTTPS/WSS 检查，核对升级前后历史数据和成果可用性，记录部署版本及回滚位置。

## Out of Scope

- Craft 全部产品功能的移植，包括附件上传、多连接/OAuth、桌面窗口、文件系统能力及其他现有产品未提供的入口。
- 重建后端、业务状态机、调研执行链或数据库模型；新增跨设备草稿同步。
- 升级 Craft 固定基线、建立通用组件发布平台或自动上游同步系统。
- 用原型假数据、只改 CSS 或本地重新实现相似组件替代实际源码迁移。
- 承诺所有业务 UI 都有 Craft 对应原组件，或以未经核实的复用百分比验收。
- 清理无关服务器目录、服务、数据或历史代码。

## Further Notes

本规格依据 ADR-0002 和本次已确认的测试入口。既有 R3 规格继续约束用户可观察行为，复用标准与局部视觉冲突采用本规格的明确决定。

当前发布的是范围与验收规格，尚未完成上游恢复和核心链路运行验证。进入全量页面迁移前，必须用前置验证结果补齐逐组件方案；若发现影响范围或用户行为的新取舍，记录并确认后更新规格。后续拆票应将源码核查和核心链路置于依赖最前端，避免下游任务使用未验证的组件接口。
