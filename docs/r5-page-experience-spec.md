# Spec R5：Craft 页面体验与 A 三段工作台

发布记录：[GitHub Issue #51](https://github.com/kassol/AgentAnywhere/issues/51)。

## Problem Statement

R4 已迁入 Craft 原组件，但页面组织仍延续早期表单和状态展示方式。长指令占据标题、关联工作与状态卡重复、运行细节挤占阅读空间，使用户难以快速判断工作进展、需要介入的事项和可阅读的成果。组件复用完成后，整体体验仍未达到用户期待。

用户已选择 R5 原型 A。正式产品需要落实这套页面体验，同时保留已交付的业务能力、历史数据和操作保障。

## Solution

以 R5 A 三段工作台为唯一页面基准：独立导航、会话列表、对话主区，报告按需打开；管家对话承担日常委托入口，工作与待办可直接访问。统一字体、密度、面板比例、消息节奏、输入区和报告阅读体验。

对话与工作使用简短、可编辑的显示标题。每项工作有一个集中入口，默认呈现当前状态、成果和需要介入的事项；原始要求、历史执行、工具参数与精确身份可展开核查。所有操作连接真实业务，升级继续保留已有链接、草稿、报告版本和模型配置。

## User Stories

1. 作为工作台所有者，我希望进入应用后以管家对话为主线，以便直接开始讨论与委托。
2. 作为所有者，我希望导航、会话列表和对话区域各有稳定位置，以便快速定位内容。
3. 作为所有者，我希望搜索并切换历史对话，以便继续已有工作。
4. 作为所有者，我希望新建对话显示明确空态，以便理解输入入口。
5. 作为所有者，我希望对话自动获得简短标题，以便识别历史话题。
6. 作为所有者，我希望工作自动获得简短标题，以便浏览多个目标。
7. 作为所有者，我希望手动修改对话和工作标题，以便使用自己的命名方式。
8. 作为所有者，我希望自动命名失败时仍有可读摘要，以便继续使用工作台。
9. 作为所有者，我希望后来返回的自动标题保留我的修改，以便避免人工编辑丢失。
10. 作为所有者，我希望查看完整原始要求，以便核对执行目标。
11. 作为所有者，我希望改名仅影响展示，以便保持工作身份与执行约束稳定。
12. 作为所有者，我希望同一对话中的每项工作只有一个集中入口，以便避免反复辨认重复卡片。
13. 作为所有者，我希望工作入口优先显示当前状态、报告和待回答事项，以便知道下一步操作。
14. 作为所有者，我希望展开查看历史执行与操作回执，以便追溯错误和恢复过程。
15. 作为所有者，我希望多个工作各自保持独立状态，以便识别部分完成、部分等待的情况。
16. 作为所有者，我希望工作列表可直接访问，并保留直接创建工作的能力，以便按当前需要选择入口。
17. 作为所有者，我希望待办集中列出全部未解决事项，以便逐项回答或决定额度。
18. 作为所有者，我希望从任一入口回答后其他页面同步更新，以便避免重复介入。
19. 作为所有者，我希望看到失败原因与可用重试动作，以便从可信位置恢复工作。
20. 作为所有者，我希望清楚区分停止管家回复与取消工作，以便控制正确的执行对象。
21. 作为所有者，我希望快捷操作保留精确目标并让我检查授权内容，以便避免操作相似标题的另一项工作。
22. 作为所有者，我希望输入区支持中文输入法、Enter 发送和 Shift+Enter 换行，以便可靠输入要求。
23. 作为所有者，我希望草稿按对话保存，并在发送失败或刷新后保留，以便继续编辑。
24. 作为所有者，我希望发送期间的新编辑受到保护，以便旧响应不会清空新内容。
25. 作为所有者，我希望阅读历史时新消息不抢走位置，以便连续阅读。
26. 作为所有者，我希望工具详情默认收起且仍可查看，以便兼顾阅读与核查。
27. 作为审阅者，我希望从工作入口打开报告并保留对话上下文，以便边读边讨论。
28. 作为审阅者，我希望独立阅读报告，并能返回来源位置，以便专注审阅。
29. 作为审阅者，我希望版本切换与下载指向明确的不可变版本，以便核对历史成果。
30. 作为审阅者，我希望批注绑定工作及报告版本，以便改稿目标明确。
31. 作为审阅者，我希望刷新恢复未提交批注，并在引用失效时保留原文，以便不丢失审阅意见。
32. 作为审阅者，我希望汇总批注后检查并发送改稿要求，以便明确授权新执行。
33. 作为审阅者，我希望出现新版时选择继续原版或取消，以便避免目标被自动替换。
34. 作为审阅者，我希望改稿完成后旧版仍可读，提交仅清理实际接受的批注，以便保留历史与后续编辑。
35. 作为所有者，我希望设置完整保留连接、协议、管家模型和人工调研模型池，以便继续使用已有配置。
36. 作为所有者，我希望配置错误、加载和保存失败有清晰反馈，以便知道数据是否已生效。
37. 作为所有者，我希望登录与退出使用真实鉴权，并有明确错误状态，以便保护自己的数据。
38. 作为所有者，我希望六类页面使用一致的 Craft 字体、控件与间距，以便获得连续的产品体验。
39. 作为所有者，我希望浅色、深色和跟随系统均保持可读，以便适应不同环境。
40. 作为小屏用户，我希望导航、输入、介入、报告和返回操作都可达，以便完成同样的主要流程。
41. 作为键盘用户，我希望焦点与控件名称明确，以便完成导航、改名、输入及报告审阅。
42. 作为所有者，我希望长标题、长消息、多工作和空态均保持稳定布局，以便持续使用。
43. 作为所有者，我希望升级保留既有对话、工作、成果链接与本机草稿，以便继续原有任务。
44. 作为维护者，我希望核查实际组件来源及页面与 A 的差异，以便避免再次出现原型与交付脱节。

## Implementation Decisions

- **基准与优先级**：遵循 ADR-0003；R5 A 原型提交 `412e7d0` 是页面组合、密度、层级和交互比较基线。R3 同名 A 不再约束整体布局。R4 的来源、许可和原组件复用要求继续有效。安全、数据保护、可访问性与现有业务契约优先，必要视觉适配需记录理由。
- **涉及模块**：调整应用外壳、会话导航、管家对话、工作列表与详情、全局待办、报告预览与批注、设置、登录及主题；扩展管家对话与工作存储的展示信息。复用现有业务服务和前端行为模块，避免另建一套执行状态机。
- **Craft 复用**：固定 Craft Agents OSS v0.13.3、提交 `e8963854c3679edcceb105a42537a06749e6cb64`，优先使用已迁入且实际运行的组件与主题。需要追加上游页面源码时先核查依赖并记录来源、适配和许可。业务页面以原组件组合，不能声称全部页面均有上游对应实现；已有对应组件的重写例外仍须按已采纳规则确认。
- **布局与导航**：实现 A 的独立导航、会话列表、主内容与按需报告面板；报告独立阅读时使用完整主区，关闭后恢复合理来源上下文。会话搜索至少覆盖显示标题，清空搜索恢复列表；新建与切换对话展示各自真实内容。工作和待办有可直接访问的页面，待办入口展示全量未解决事项，保留原有工作直达链接。
- **报告入口**：从具体工作进入时固定工作与报告版本；独立报告入口没有目标时提供可选择的成果或空态，禁止默认绑定任意样本。保留原有深链接、刷新与浏览器返回行为；小屏按需切换单区阅读并提供明确返回入口。
- **显示标题持久化**：对话和工作各自保存显示标题及足以区分人工编辑与自动命名的状态。原始消息、工作目标、请求身份及执行输入保持原样。既有对话标题继续可读；旧工作缺少标题时使用目标摘要，无需阻塞式批量模型回填。
- **自动命名**：对新对话与新工作生成概括目标的短标题，允许必要模型调用；先显示摘要，再接受有效结果。模型失败、空结果或超时回退摘要，命名失败不得阻止讨论与执行。复用现有模型连接与协议适配，明确限制调用次数和耗时并记录用量，不开放工具执行或绕过现有执行额度。避免每次刷新重复调用；人工改名后的迟到结果不得覆盖已保存标题。
- **改名接口**：沿用公开 API 的鉴权、来源检查和对象身份，补充对话与工作的标题更新操作以及列表、详情、关联工作和待办所需展示字段。验证非空、长度上限和对象归属，错误可见且保留编辑；成功后所有相关视图和刷新后的内容一致。具体字段及端点在实施票据中固定，接口只改变展示信息，不接受借改名修改目标、模型或执行状态。
- **工作集中入口**：以 Task 身份聚合同一对话中的工作，合并现有关联工作和状态卡的展示。当前状态、有效待办、报告版本与可用动作来自真实服务端数据；历史 Run、工具结果和 Operation 回执在该工作下展开。对话保留关键事件，避免同一工作形成重复的完整操作卡。重复或同名标题不合并不同 Task，旧 Run 的终态不覆盖新执行。
- **工作与介入**：保留直接创建、追加要求、取消、额度决定、回答、失败重试、完成后继续及改稿能力。标题只参与展示，操作仍携带既有 Task、Run、Interaction、Operation 或 Version 身份。等待后恢复的执行代次、重试产生新 Run、跨轮回执恢复及幂等语义继续成立；回答成功不能直接伪造工作完成。
- **输入与阅读**：沿用可靠输入、按对话草稿、发送身份、中文组合输入保护、覆盖确认和旧响应保护。流式活动保留轮次归属，详情默认收起；历史阅读保持位置并可回到最新。布局切换与打开报告不丢失未发送内容。
- **报告与批注**：使用真实安全 Markdown、不可变版本内容与下载接口；版本切换、滚动位置、批注隔离、引用失效、新版确认和接受后精确清理沿用已有契约。改稿必须经用户发送后进入真实执行，每个工作的版本和正文独立，不能复用原型的全局版本集合或预置响应。
- **设置与登录**：沿用完整单连接、凭证保护、模型发现、双协议、能力设置、人工调研模型池与在途快照语义。主题保留本机偏好及跟随系统行为。原型简化表单不删减正式能力、不引入隐式备用模型规则；登录继续真实鉴权，未认证页面不得显示私有对话或提供绕过登录的返回入口。
- **字体与样式**：继续使用已确认的自托管 Inter、Craft 主题及中文系统回退；逐页核查真实加载、字号字重、面板宽度、列表密度、边界、滚动和焦点。原型切换器、状态检查器及模拟按钮不进入正式页面。修正本轮替换造成的孤儿样式，避免全局旧 CSS 覆盖原组件。
- **迁移与交付**：采用兼容的展示字段迁移，保留旧数据、公开链接和草稿格式，必要格式变化提供兼容读取或迁移。按现有项目流程部署到已指定环境，记录发布版本、备份、回滚与上线复验；只清理本轮临时产物。原型继续独立保存。

## Testing Decisions

产品所有者已确认两层验收入口：公开 API 行为回归，以及 ego-browser 真实流程与 A 原型逐页视觉对照。复用现有最高层入口，不为本轮建立新的通用测试平台。

1. **可观察行为**：以保存、读取、刷新、操作结果和数据身份为断言；不锁定组件树或私有函数。复用已有真实 PostgreSQL、应用 HTTP 服务、报告内容与下载、工作精确目标的集成检查，以及输入、预览、批注、快捷操作和设置行为回归。
2. **标题契约**：经公开接口验证对话与工作改名、非法输入、未认证/无归属目标、刷新持久化和多入口一致性。确定性控制自动命名的成功、失败、超时、重复触发与迟到结果，验证人工改名受保护、原始要求和请求幂等身份不变；再用真实模型连接验证正常命名链路。旧数据迁移可重复执行，缺少标题时正常回退。
3. **集中工作与跨入口状态**：覆盖一段对话关联多个工作、同名工作、多 Run、等待问题与额度决定、失败重试、旧回执以及多版本成果；每 Task 一个集中入口，详情仍可查。回答后在管家、工作和待办同步，旧响应不把新执行改成旧状态。执行与授权相关变更复用真实隔离链路，缺少独立测试库须明确失败。
4. **真实完整流程**：用 ego-browser 完成登录、新建与搜索对话、委托多项工作、查看进度、回答与恢复、失败重试、打开真实报告、批注汇总、发送改稿、读取并下载新旧版本。验证直接创建工作、停止与取消、设置保存及错误反馈；模拟原型或只通 API 不构成浏览器验收。
5. **数据保护与键盘**：覆盖中文输入法、换行、发送失败、刷新草稿、提交中继续编辑、快捷命令覆盖的确认与取消、新版提示、批注恢复及精确清理。覆盖焦点返回、键盘改名、移动导航、输入区和报告操作；工具无法完成的检查明确标为未验证。
6. **页面矩阵**：管家、工作、待办、报告、设置、登录均覆盖浅深主题及小屏，另验证跟随系统；包含空态、有历史、长内容、多工作、执行中、等待回答、失败、多版本、加载和请求错误。以 1440×1000 与 390×844 为可比较视口，辅以打开/关闭报告时的宽度变化。
7. **视觉验收**：使用与 A 可比较的内容和状态保存截图，逐页检查导航与会话分栏、阅读宽度、层级、消息与列表密度、输入区、报告排版、主题和中文字体回退。列出实际差异及理由；横向无溢出和功能测试通过均不足以证明通过。检查原组件源码实际参与渲染，更新来源和适配证据。
8. **发布门槛**：完成构建、类型检查及项目要求的有效回归；正式环境核对部署版本、历史数据与成果访问、鉴权、资源字体及 HTTPS/WSS。明确区分本地检查、隔离真实执行、正式环境复验和剩余未验证项。

## Out of Scope

- B/C 布局、永久布局选择器、原型状态检查器和模拟执行能力。
- Craft 全产品复制、上游基线升级、Electron 运行时、附件上传、多账号或 OAuth 等新增产品能力。
- 改变授权、工作执行、额度、恢复或不可变成果语义；以展示标题替代业务身份。
- 新建后台状态机、通用组件平台、通用搜索服务或跨设备草稿同步。
- 对全部历史对象执行付费模型回填，或每轮对话自动重命名已由用户编辑的标题。
- 删除原型未展示的既有正式能力，或以演示验证取代真实发布验收。
- 清理无关服务器目录、服务或用户数据。
