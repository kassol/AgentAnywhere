# R3 可操作 UI 原型

状态：2026-09-20 用户选择 A 经典侧栏为 R3 基准，并要求进入 to-spec。代码不作为正式实现直接发布。

## 要回答的问题

在 Craft 交互基准下，管家对话、关联工作和报告审阅如何组织，才能在处理工作时保留对话上下文？范围来自 [R3 已确认决定](r3-ui-decisions.md)。

同一首页提供三个结构变体：A 经典侧栏、B 紧凑导航、C 工作队列优先。均保留中间对话及按需右侧预览。底部切换器和 URL `variant=A/B/C` 用于比较；用户已选择 A 为基准，B/C 保留为比较材料。

## 运行

```sh
bun install --frozen-lockfile
bun run prototype:r3
```

入口：<http://127.0.0.1:19120/?prototype=r3&variant=A>。只在 Vite 开发模式启用，正式构建不包含原型入口。现有正式页面的登录与数据请求不变；原型使用独立演示数据，不连接业务 API。

为便于本轮体验，评审期间保留本机 `19120` 服务及结果页；停止服务后用上述命令重启。无需远端环境或模型凭证。

代码位于 `src/web/R3Prototype.tsx`、`src/web/r3-prototype.css`，保存在 `prototype/r3-craft-ui` 分支。Craft 提取来源及限制见 [上游记录](r3-prototype-upstream.md)。

## 体验路径

1. 切换 A/B/C，比较导航、工作定位和报告阅读占用的空间。
2. 选择执行、等待回答或失败场景，展开工具详情，点击快捷操作，检查聊天框内容后发送。
3. 打开报告，选中文字添加多条批注，汇总到聊天框，确认后发送改稿。
4. 在旧版报告批注后模拟新版出现，检查旧版提示；模拟发送失败，确认草稿保留。
5. 切换对话、报告及刷新页面，检查各自草稿恢复；切换深色和小屏，检查返回路径。
6. 打开设置，分别检查日常模型选择和网关详情。

原型专用本机存储仅用于验证已确认的草稿与刷新恢复行为；工作过程与报告采用预置演示数据；发送演示消息入流、失败留存及批注清理，尚不生成真实报告或驱动完整工作状态机。正式鉴权、幂等及后端恢复继续由后续实现验收。

## 验证与结论

2026-09-20：`bun run typecheck`、`bun run build`、`git diff --check` 通过。正式构建只输出原应用资源，原型动态入口被开发模式条件排除。

同一个 ego-browser TaskSpace 33 完成：

- A/B/C 切换、URL 保持；输入框内方向键不切换方案。
- 工具详情展开、回答选项填入对应内容、失败重试填入草稿；Shift+Enter 换行及 Enter 发送。
- 鼠标选择报告文字、添加批注、汇总入聊天、模拟发送失败、刷新恢复；成功发送后只清除本次批注。
- v1 批注汇总后刷新再发送，仍提示新版；取消保留草稿，确认后消息进入流。
- 深色设置与网关详情；390px 单面板报告、返回对话和草稿保留，无横向页面溢出。
- 报告 `.md` 实际下载内容与预置版本相符。

初查发现的消息属性漏传、未提交批注误清理、刷新丢失汇总绑定、两个回答选项填入相同内容、窄屏切换条遮挡输入等问题已修正。新增消息保留阅读位置与回到最新入口由源码核查，尚未覆盖长对话自动滚动的全部情形。
