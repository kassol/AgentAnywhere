## Problem Statement

所有者已经可以在 R1 工作台创建公开资料调研、观察执行、回答问题并取得持久报告。当前入口要求用户自行将需求整理成工作，进入各项工作查看状态和操作；普通讨论、目标澄清、跨工作查询及报告解读缺少统一的持久对话入口。每项工作的模型也需要用户选择。

R2 要让所有者在管家对话中完成讨论、委托和介入，同时保持现有工作状态、授权、成果和执行边界。管家应准确报告真实操作结果，明确区分讨论、调研执行与报告修改。

## Solution

将管家设为默认首页，支持新建和重新打开多段独立对话，保留工作列表、直接创建及工作详情。明确的调研委托直接创建工作，关键缺项或目标不明时先提问；普通问答和已有报告解读在管家对话内完成，需要新资料时交给现有调研执行。

用户配置管家模型并维护人工选定的调研模型池。管家按质量优先，从有效候选中选择工作模型，展示模型、选择理由和实测状态。管家通过受限能力调用现有工作操作，关联工作状态回传所有相关对话，全局待办按同一问题去重。管家轮次串行执行，与调研的单项执行名额独立。

本规格来自已整体确认的 R2 访谈，范围和测试策略已确定。2026-09-19 已实现并发布，逐项验收见 [R2-12](evidence/r2-12.md)。

## Implementation Decisions

### 对话与领域对象

- 区分管家对话、管家轮次和工作对话。管家对话是一段可独立持久化的 Thread，可以关联多项 Task；工作对话仍围绕一项 Task。管家轮次处理一条用户消息，保存其回复与工作操作结果，不等同于调研 Run。
- 当前工作创建会同时建立 Task、Thread、Run 和用户消息；现有工作消息只覆盖用户要求。新增独立管家对话、管家回复与轮次持久化，保留既有工作和历史语义。数据演进必须使 R1 工作、事件及成果仍可读取。
- 建立管家对话与 Task 的多对多关联。明确引用或操作历史工作时建立关联；仅查询候选不关联。多段对话引用同一个 Task、Run 和 Interaction，不复制业务事实。
- 管家只读取本段对话及按用户要求检索的工作、报告；其他管家对话内容不自动加入。查询结果保留工作、Run 或成果版本引用，避免把旧报告与新状态混为一谈。
- 管家首页提供新对话和历史对话入口；原有工作列表、直接创建、详情和模型设置继续可用。工作卡可进入原工作详情，详细工具活动保留在工作详情。

### 管家轮次与受限操作

- 普通讨论不创建调研 Task 或 Worker Sandbox。为管家建立独立于调研 Run 的受限模型调用与轮次执行边界，复用现有模型连接、认证和协议能力；不把管家伪装成一项占用调研名额的工作。
- 管家可以创建、查询、追加、回答、取消、手动重试和继续工作，调用与现有 Web/API 一致的业务操作和状态检查。管家不持有宿主 shell、任意数据库查询、Docker/Sandbox 管理或外部账号操作能力。
- 目标清楚的明确委托直接执行。关键缺项先问；指代多个可能工作时先澄清。普通解释、摘要和明确请求的已有报告比较直接回答；明确要求修改或保存新版报告时，沿用原 Task 创建新 Run，含糊时先问。
- 获取新搜索结果或公开网页正文必须派发调研工作，管家不新增直接检索工具。一条消息可建立多项独立工作，受单轮创建上限约束；不建立父任务，不自动汇总多个工作。
- 用户消息提交、轮次推进和工作操作需有稳定的请求身份及持久回执。重复提交、重连、工具结果丢失和服务中断后继续必须查询已接受结果，避免重复动作。幂等约束落在实际业务写入边界，不能只依赖模型记住已执行操作。
- 多项操作可以部分成功。停止、触顶或后续失败时，清楚列出已接收、失败和未执行的部分；已创建工作保留并继续，不能回滚或掩盖已发生动作。用户明确取消某项工作时才调用取消行为。
- 管家与工作详情操作同一份 Interaction。首次有效回答完成该问题；重复、冲突和已过期回答沿用服务端状态检查，不能生成重复恢复。被询问时管家不能替用户虚构回答或擅自同意增加调研额度。

### 模型连接、模型池与替代

- 沿用单套 ModelConnection、服务端凭证、人工覆盖及元信息来源优先级。配置管家模型及其协议，同时维护人工选定的调研模型池；网关发现列表不自动成为调研授权池。
- 管家模型和工作模型可以不同。管家按任务需要、可信能力资料与已有实测记录，以结果质量优先选择池内模型；不编造性能排名或从模型名称推出能力。选择理由、所用模型、元信息来源与验证状态可见。
- 人工入池、运行必要参数完整且有工具支持依据的模型允许尝试。没有成功记录时标注尚未实测；目录声明、连接成功和实际工具能力验证应分别表述。
- 模型池为空、候选缺少必要参数、明确不支持工具或已不可用时，说明缺项并停止派发；不能偷偷使用池外模型或伪造默认能力。服务端验证池成员、配置有效性和运行要求，不能只在模型提示中约束。
- 管家和调研均支持 Chat Completions 与 Responses，保持协议选择与实际请求一致。每轮管家处理及每个 Run 固定有效模型/协议/参数与凭证版本；后续配置变化只作用于新轮次和新 Run。
- 保留直接创建工作的现有行为。升级时保留既有模型选择和有效配置；新管家配置缺失应明确引导设置，不丢弃或静默重写 R1 配置。
- 模型错误采用有限重试，所有实际请求受本轮 8 次调用及 5 分钟活跃时间硬上限约束；不可重试错误或重试耗尽时停止并保留历史、进度及实际错误，管家可建议有效替代模型；用户明确重试后才创建关联的新 Run。不得在原 Run 内静默切模型或自动降级协议。
- 现有手动重试固定沿用原 Run 的模型快照。R2 必须补充显式替代模型的新 Run 路径，保留重试关联与旧记录；从旧进度恢复时验证模型/协议兼容，不重放已完成操作，不把原始会话记录跨模型可直接使用当作已验证事实。保留检查点来源链、文件哈希校验和待处理要求；不把旧 Interaction 回答误注入新的执行。无法兼容恢复的候选明确拒绝，保留原检查点和成果并说明原因，不自动丢弃进度后从头执行；为同模型及兼容替代模型分别提供成功恢复证据。

### 调度、停止、恢复与额度

- 管家全局只生成一轮回复，其他轮次排队；每段对话按消息顺序处理。调研保持一个活跃 Worker Run，两个执行名额独立，管家查询和控制不被长调研阻塞。
- 管家回复完成、提问、触顶、失败或停止后释放其执行名额。页面关闭或刷新不取消服务端已接收的轮次。服务重启中断需明确展示，用户继续后核对已接受操作再处理剩余内容，不自动重放整轮。
- 停止排队轮次会撤销其排队；停止正在生成的轮次会中止模型响应和后续工具派发。停止请求到达前已被业务服务接受的操作如实保留，已创建调研工作继续；明确取消工作采用独立工作取消操作。
- 每轮管家最多 5 分钟活跃处理、8 次实际模型请求、成功创建 3 项新工作。网络重试及自动摘要调用计入模型请求次数；相同创建请求的幂等重试不重复占用工作创建数量。调研 Run 保持原有 45 分钟、40 次模型调用规则。
- 排队和等待用户输入不计入活跃时间。额度由服务端控制，到达任一上限即停止新请求/新操作，保留结果并说明触顶原因；用户明确继续后获得下一轮预算，已接受的操作不重放。时间与计数不会因刷新或重启无声重置。
- 持久化回复、工作操作回执与恢复所需状态，流式事件有顺序和去重身份。界面恢复以服务端事实为准，模型生成的“已创建”“已完成”不能替代真实回执。

### 摘要、状态卡与全局待办

- 接近当前模型上下文上限时自动摘要较早讨论，保留原消息可查；摘要显示覆盖范围，保留用户目标、确认约束、关联工作引用和待处理事项。近期消息与必要操作结果继续作为上下文。
- 摘要不是工作状态源；回答当前进度和引用成果时读取真实工作状态与对应成果版本。摘要失败时停止本轮并提示，保留原文与此前操作结果，不静默截断重要历史。
- 完成、失败、提问及额度等待等关键工作状态，向所有明确关联的管家对话投递对应状态卡。卡片引用同一工作和 Interaction，事件重放、刷新及补投递不会生成重复卡片或重复问题。
- 全局待办显示全部尚待用户回答的 Interaction 数量，包括直接创建及其他对话的工作；同一问题只计一次，链接到可操作位置。任何入口回答后同步更新相关卡片与待办，不能另建一份管家专用问题。
- 状态卡使用已持久化事实展示；无需为后台状态变化自动发起额外模型总结。用户提出解读或比较时才进入新的管家轮次。

### 安全与兼容

- 现有登录、HTTPS/WSS、Origin 检查及成果访问保护覆盖新增入口。长期凭证不进入对话、报告、日志或前端可回读字段。
- 网页、报告、搜索内容及摘要中的引用资料是待分析数据，不能冒充用户授权。受限工具及服务端校验共同约束操作目标、允许模型、预算和状态。
- 保持既有受控资料访问和安全 Markdown 渲染，管家引用成果仍遵循安全链接与活动内容限制；不新增通用网页执行或外部写权限。
- 部署继续仅使用指定 cc-la 的独立资源；迁移、恢复和回退保留 R1 工作及成果。沿用现有部署、备份和回退流程，不以删除旧数据完成结构调整；本版验证新增迁移的 R1 兼容性。

## Testing Decisions

已确认采用一个主验收入口，从真实 Web/API 验证可见行为、持久化、操作回执和资源后置条件。沿用现有统一测试入口的隔离、真实模型和公网阶段，扩展管家场景；三个阶段分别执行，发布需要全部通过，单独执行隔离阶段不代表完成发布验收。隔离入口还需纳入真实 PostgreSQL 的公开 API 回归，并在数据库缺失时明确失败；内部业务状态、数据库、调度及调研 Sandbox 均保持真实，仅外部模型与搜索 HTTP 响应可控。管家设计上不创建 Sandbox，其派发的调研必须进入真实执行链路。

最高层测试覆盖管家对话及轮次、模型配置与选择、现有工作操作、摘要、关联状态卡和全局待办。测试以“发生了什么、用户看到了什么、保存了什么、资源是否释放”为断言；不把内部函数调用次数、私有表布局或提示词字面内容作为主要验收。边界时间允许使用服务端测试时钟，生产入口不接受测试时钟或预算覆盖。完整验收必须提供真实独立测试数据库；数据库缺失导致跳过的测试不能记为通过。

现有先例包括：经真实 HTTP/API 和独立 PostgreSQL schema 验证持久化及幂等；统一链路验证 Pi、队列、OpenSandbox 的追加、提问、取消、恢复与成果版本；实际 SDK 核查沙箱回收；真实双协议及 SearXNG 调研；ego-browser 中文键盘、刷新、安全报告与下载哈希验收。复用这些入口，避免为每个新内部模块建立一套替身测试。

| 编号 | 外部行为与验收结果 |
| --- | --- |
| R2-T01 | 登录后默认进入管家；工作列表、直接创建、详情和设置保持可用；匿名及跨 Origin 请求受保护。 |
| R2-T02 | 新建、列出和重开多段对话；流式回复、刷新、重连及关闭页面后恢复历史，普通问答没有 Task 或 Sandbox。 |
| R2-T03 | 明确委托创建工作；缺项或工作指代含糊时先提问；需要新资料进入调研，解释已有报告直接回答。 |
| R2-T04 | 一条消息创建两项独立工作并排队执行；模型、回执、状态及成果可见；没有父任务或自动多工作汇总。 |
| R2-T05 | 人工池约束、模型能力参数、质量优先理由、未实测标注、空池和无候选提示；尝试池外或不合格模型被服务端拒绝。 |
| R2-T06 | 管家与调研分别使用配置协议；两种协议均完成真实流式和工具往返；运行中修改设置不改变在途模型快照。 |
| R2-T07 | 管家创建、查询、追加、回答、取消、重试及改稿与原工作入口一致；运行中要求在原有安全时机生效。 |
| R2-T08 | 管家和详情同时回答同一问题，重复回答不重复恢复；冲突回答有明确结果；额度等待不能由管家代替用户决定继续。 |
| R2-T09 | 按要求查历史工作与报告，候选查询不自动关联，明确引用后关联；其他管家对话内容不自动泄入上下文。 |
| R2-T10 | 工作状态投递到全部关联对话；刷新、断线和重复事件不重复卡片；全局待办按 Interaction 去重并随回答消失。 |
| R2-T11 | 管家全局串行，跨对话轮次排队且可取消；调研独立执行，长调研期间管家仍能查询和取消。 |
| R2-T12 | 停止管家模型流或排队轮次后没有新派发；已接受的操作可见、已创建工作继续；取消指定工作仍回收相关执行资源。 |
| R2-T13 | 请求重复、业务已提交但响应丢失、流断线和服务中断后继续，均核对回执而不重复动作；部分成功明确保留。 |
| R2-T14 | 5 分钟、8 次实际模型请求、3 项工作边界可复现；排队/等用户不计时，重试/摘要计数，触顶等待明确继续。 |
| R2-T15 | 接近上下文上限时摘要可见且范围清楚，原文可查；目标、约束、引用和待办保留，动态工作事实重新查询；摘要失败停下并保留数据。 |
| R2-T16 | 持续模型失败停止并建议替代；只有明确重试才以替代模型创建关联新 Run，原记录、成果与已完成步骤保留，不自动换模型；不兼容候选明确拒绝且保留进度；持续错误请求数不超过轮次硬上限。 |
| R2-T17 | 报告解读不产生新版本；明确改稿生成新 Run 和版本，旧成果在沙箱回收和应用重启后仍可读取下载。 |
| R2-T18 | 恶意报告/网页/模型输出不能越权派发、访问长期密钥或执行活动内容；普通管家没有宿主、数据库或 Sandbox 管理工具。 |
| R2-T19 | 真实中文与键盘完成“讨论→两项委托→介入→状态卡→全局待办→报告解读→明确改稿”；公网 HTTPS/WSS、下载和清理后置条件通过。 |
| R2-T20 | 迁移后 R1 历史工作、成果、模型配置和直接操作兼容；新增迁移兼容检查、沿用的部署/回退步骤、测试清理和 cc-la 既有服务对照有证据。 |

发布验收在 cc-la 使用真实 sub2api 双协议，执行管家工具往返和真实调研，并用 ego-browser 完成新增用户路径。没有真实凭据或网关能力时应报告具体阻塞，不能用可控 HTTP 响应替代发布证据。除新增行为外保留必要 R1 回归；完成针对风险的有效检查后，无新增变更或疑点即停止重复扩测。

## Out of Scope

- 父子任务拆分、动态 Agent 编排、自动多工作汇总。
- 开发执行、外部账号写入、交互式浏览器接管、定时自动化。
- 管家直接搜索/抓网页、通用 shell、任意数据库访问或 Sandbox 管理。
- 跨管家对话自动记忆、对话删除及归档管理。
- 自动从网关扩充调研模型池、无人确认的模型替换或协议降级。
- 模型质量排行榜、未经验证的性能/价格保证及第二套模型网关。
- 改变调研单并发、既有 Run 预算或报告持久化原则。
