# Spec：首个可用版本——精简 Web 与模型接入

## Problem Statement

所有者需要一个自托管工作台：配置已有模型网关，提交公开资料调研目标，观察执行并介入，最终取得可长期读取的报告。W0 已验证若干上游组件能够运行，但原生 Craft 页面包含大量无关功能，自定义模型依赖手填，模型元信息使用默认值，也尚未形成应用内的任务、隔离执行与成果留存闭环。

首个可用版本应让所有者从工作列表完成一次真实调研，同时建立后续扩展所需的 Task、Run、Interaction 和 Artifact 边界。验收针对完整用户行为，不能以原生聊天可运行替代。

## Solution

交付中文可用的精简 Web，主要入口为工作列表、工作对话和设置。所有者配置一套 sub2api ModelConnection，获取并选择模型，分别使用 Chat Completions 或 Responses；模型元信息优先采用人工覆盖，其次网关信息，再以明确匹配的 models.dev 补全，缺失项显示未知。

在 cc-la 部署独立私有 SearXNG。用户输入主题或公开链接后，工作进入队列，由 Pi 在 OpenSandbox 管理的隔离环境执行。一次只运行一项工作；界面持续展示消息、工具活动、状态和用量。用户可以追加要求、回答问题或取消。报告及附件复制到持久存储后才能报告交付成功，沙箱回收后仍能阅读和下载。完成后补充要求保留在原工作，新 Run 产生新报告版本。

本规格是完整 MVP 的首个可用增量；确认范围来源为已完成的 18 项访谈。产品需求不再等待进一步访谈，外部接口的不确定性通过工程核查和真实验收解决。

## User Stories

1. 作为所有者，我希望登录后进入工作列表，以便集中查看已有工作。
2. 作为所有者，我希望只看到本版可用的工作和设置入口，以便避免无关桌面功能与空菜单。
3. 作为所有者，我希望用中文界面和键盘操作主要流程，以便顺畅创建和管理工作。
4. 作为所有者，我希望保存一套 sub2api 端点与凭证，以便使用已有网关。
5. 作为所有者，我希望替换凭证时已有密钥不会回显，以便安全维护配置。
6. 作为所有者，我希望从网关获取、搜索和刷新模型列表，以便无需逐个手填 ID。
7. 作为所有者，我希望区分鉴权失败、网络故障和空模型列表，以便采取正确处理。
8. 作为所有者，我希望模型未被列表列出时能显式输入 ID，以便兼容网关的特殊情况。
9. 作为所有者，我希望每个模型可保存默认协议，以便新建工作时通常只需选择模型。
10. 作为所有者，我希望在高级选项中覆盖协议，以便使用该模型实际支持的 Chat Completions 或 Responses。
11. 作为所有者，我希望连接测试与正式工作使用相同模型和协议，以便测试结果能反映实际配置。
12. 作为所有者，我希望看到模型上下文和输出限制、模态、工具与推理能力，以便判断模型是否适合调研。
13. 作为所有者，我希望元信息缺失时明确显示未知，以便避免将默认值误认为真实能力。
14. 作为所有者，我希望明确匹配的 models.dev 信息能补全缺失字段，以便减少手工维护。
15. 作为所有者，我希望对网关别名显式指定映射，以便避免同名或近似名称错配。
16. 作为所有者，我希望人工修改元信息并查看来源，以便适配网关的实际限制。
17. 作为所有者，我希望参考价格、估算费用和实际费用分开显示，以便避免把未知费用误认为免费。
18. 作为所有者，我希望选择默认模型及每项工作的模型，以便按目标分配推断能力。
19. 作为所有者，我希望以调研主题新建工作，以便无需预先寻找全部资料。
20. 作为所有者，我希望附上公开链接，以便指定必须参考的来源。
21. 作为所有者，我希望使用自己的 SearXNG 私有实例，以便独立管理搜索服务。
22. 作为所有者，我希望搜索或网页读取失败能如实显示，以便识别报告资料的不足。
23. 作为所有者，我希望在工作对话中看到流式输出和工具结果，以便理解当前进展。
24. 作为所有者，我希望追加要求后看到待处理状态，以便知道要求已经保存。
25. 作为所有者，我希望追加要求在当前工具结束后生效，以便保留已完成的资料获取。
26. 作为所有者，我希望 Agent 提问时工作等待回答，以便由我决定仍有歧义的方向。
27. 作为所有者，我希望等待期间释放沙箱和执行名额，以便避免长期占用资源。
28. 作为所有者，我希望回答后恢复资料和进度，以便无需从头提交目标。
29. 作为所有者，我希望同时提交的工作排队逐项执行，以便控制服务器负载。
30. 作为所有者，我希望取消正在执行或排队的工作，以便及时停止后续动作。
31. 作为所有者，我希望取消后仍能看到已完成的步骤和已保存成果，以便掌握实际发生的情况。
32. 作为所有者，我希望短暂错误有限重试、持续故障停下并保存进度，以便避免无限消耗。
33. 作为所有者，我希望失败或服务重启中断后能在原工作中手动重试，以便保留上下文和历史。
34. 作为所有者，我希望看到执行时间和 token 用量，以便理解资源消耗。
35. 作为所有者，我希望每次执行受 45 分钟活跃时间和 40 轮模型调用限制，以便控制任务规模。
36. 作为所有者，我希望到达上限时保存进度并等待我的决定，以便明确控制是否继续。
37. 作为所有者，我希望在线阅读带引用链接的 Markdown 报告，以便检查论据及其来源。
38. 作为所有者，我希望下载 Markdown 和已产生的附件，以便在工作台之外使用成果。
39. 作为所有者，我希望沙箱回收和服务重启后仍能查看已交付报告，以便可靠留存成果。
40. 作为所有者，我希望完成后继续在原工作提出修改要求，以便生成新的报告版本而保留旧版。
41. 作为所有者，我希望刷新或重连页面后恢复正确工作状态且没有重复消息，以便继续观察执行。
42. 作为所有者，我希望任务工具与外部网页接触不到长期凭证和宿主机管理权限，以便安全执行公开资料调研。

## Implementation Decisions

### 工程与复用

- 使用独立 AgentAnywhere 工程，保留适用的 Craft 样式、消息、工具卡、输入框、预览和平台适配代码；固定已验证的 Craft/Pi 来源，记录许可、来源版本和本地补丁。
- 先分析实际依赖，再提取必要模块；同时删除无关菜单、路由、服务端处理器、RPC、构建脚本和直接依赖。隐藏入口不能替代物理裁剪。正式构建不下载 Electron，不保留桌面特权模块和宿主机 Agent shell 路径。
- 沿用已确认的 React/TypeScript Web、Bun 控制服务、Node.js 队列进程、PostgreSQL/pg-boss、Pi 与 OpenSandbox 方向。W0 的 Pi 独立 Node 运行时及启动失败回传修复必须保留等价行为；进程退出需及时反馈，不能挂起到前端超时。
- 当前仓库尚无正式产品实现。这里定义需建立的模块及外部行为，不把拟议组织结构当成现有接口。研究执行能力限制在本版的单一调研角色；不建设 Agent 编辑器或多角色委派。

### 模型连接与发现

- 仅一套 ModelConnection，包含端点、凭证引用、模型集合和默认模型；每模型保存默认协议及可追溯的元信息。ModelConnection 与第三方账号 Connection 分开。
- 凭证由服务端保存，Web 不回读明文。服务端代理模型发现、元信息同步及连接测试。刷新失败保留最后成功结果并标明状态；不得用空失败响应覆盖已有选择。
- 通过网关 GET /v1/models 获取可用模型；列表不可用时提供明确的手填备用入口。模型出现在列表中仅表示网关列出它，调用及能力仍须独立验证。
- Chat Completions 与 Responses 均为本版硬验收项，配置、测试、Pi Worker 实际执行及事件转换必须使用同一协议。协议错误明确显示，不静默切换另一协议。
- 每个 Run 固定模型、协议及有效配置快照，修改设置不改变正在执行的 Run。新建工作可以覆盖默认模型和协议。
- 元信息逐字段采用人工覆盖、网关信息、明确匹配的 models.dev、未知的顺序；人工覆盖可撤销并恢复下一来源。刷新不覆盖人工值。仅明确身份匹配可自动补全，别名由用户显式映射，禁止名称模糊推断。
- 保留来源与更新时间；目录描述、人工配置和实测能力分开记录。models.dev 获取失败不阻止已有配置运行，有可用缓存时展示其状态；无缓存且必要运行参数缺失时提示补充。运行时需要的参数应明确验证，不能偷偷填入上游默认能力并展示成已知事实。
- 元信息覆盖上下文、输出上限、输入模态、工具和推理能力、协议与价格；展示能力不代表本版支持上传所有模态。自定义模型定价与目录参考价分离，缺失 usage/价格保持未知，估算带标记。
- sub2api 实际版本、模型列表扩展字段和 Responses 行为仍需在实施开始时核查；models.dev 的线上获取和具体映射也需验证。遇到缺字段采用已确认的未知/人工补充行为，不扩大成第二套模型路由平台。

### 搜索与网页读取

- 在 cc-la 新建独立私有 SearXNG，启用 JSON 搜索；由受控服务调用，工作只获得限定的搜索和公开网页读取能力。保留现有服务，不开放无鉴权公共搜索入口。
- 搜索调用 SearXNG 的 /search 接口，返回来源标题、URL、摘要及可用的时间等字段；语言/时间过滤以实际引擎支持为准。记录失败和部分结果，不把引擎不可用解释为没有资料。
- 网页读取使用 HTTP 文本提取，不依赖交互式浏览器。不可读取、需登录或需要脚本渲染的页面如实报告。正文、搜索摘要与模型推断在引用处理中保持可区分。
- 不复用 Craft 固定指向官方 OpenAI 的搜索路径；模型凭证只能用于配置的模型网关。搜索服务配置与 ModelConnection 分离。
- 公开网页工具校验初始请求及每次重定向，禁止访问 loopback、私网、云元数据和控制面；私有 SearXNG 通过专门的受控搜索入口访问，不能因此开放通用网页工具访问整个私网。

### 工作、执行与交互

- Task 保存目标和工作状态；Thread 保存工作对话；Run 保存一次执行及固定配置、限额、失败信息与重试关联。Interaction 持久保存提问及回答，SandboxLease 记录实际沙箱生命周期，Artifact/Version 保存持久成果。
- 工作可以排队、执行、等待回答、完成、失败或取消；界面明确区分排队与等待用户。一项工作只允许一个有效执行代次，系统同时只运行一项工作。旧代次不能继续提交有效动作或覆盖新结果。
- 追加要求先持久化并标为待处理；当前工具结束后，在下一次模型步骤前纳入。正在流式输出时不强行改写已发出的模型请求，在下一个模型步骤处理；完成前仍有待处理要求时必须纳入或明确保留为可继续处理项。
- Agent 提问后，先保存会话进度、必要工作文件和 Interaction，再释放沙箱与执行名额。回答后以原 Run 的新 epoch 重建沙箱并恢复，不承诺恢复内存进程。等待时长不计活跃执行时间，问题不得通过空回答自动解决。
- 完成后的追加要求创建同一 Task 下的新 Run，并保留报告历史。持续失败、服务重启中断后的手动重试新建 Run，关联前次执行。运行被中断后先核实并回收旧资源，避免重新启动时双重执行。
- 短暂模型/网络错误有限重试；不重放已完成的工具结果。持续故障保留已持久化进度并停止。通用断点自动续跑不在本版，用户显式重试后才恢复执行。
- 取消立即确认已接收并停止派发新动作，传递取消到模型与正在运行的工具，完成必要保存和资源回收；已经发生的动作和已保存产出如实保留。不能以停止前端显示代替停止后台执行。
- 每 Run 最多 45 分钟活跃执行、40 轮模型调用；等待不耗活跃时长，到达上限保存进度并等待明确继续决定，未回答不重置预算或自行运行。
- 持久化事件支持刷新/重连恢复，使用服务器顺序和去重标识避免重复消息、工具结果和 Interaction；完成、失败、取消以服务端事实为准。

### 成果与部署

- 报告为带来源链接的 Markdown，提供在线阅读、历史版本及下载；其他实际产出作为附件保存。引用支持用户检查事实来源，不宣称由程序保证所有结论正确。
- Markdown、网页来源内容与附件按不可信内容处理；预览清理脚本和危险链接，活动内容隔离于应用来源，按安全文件类型处理和下载，不能让报告执行应用权限下的脚本。
- ArtifactStore 独立于 Sandbox，先复制并校验成果，再提交版本和交付状态；保存失败不能标记交付成功或丢弃唯一副本。回收失败要保持可见并可重试。
- 凭证不进入 Prompt、普通工作文件、报告、公开日志和仓库；Worker 不持有 Docker socket 或数据库管理凭证。固定镜像与资源限制，沿用 W0 验证的非 root/gVisor 基线并验证正式链路。
- 指定部署目标为 cc-la。产品入口保留登录和 HTTPS/WSS 保护；SearXNG、模型配置和成果访问均纳入鉴权边界。W0 独立环境保留/回收事项与正式发布分别记录，避免误删现有配置。

## Testing Decisions

用户已确认一个主测试入口：从真实 Web/API 贯穿控制服务、队列、Pi 与真实沙箱，验证可见结果、持久化和资源回收。日常回归只在外部模型与搜索 HTTP 边界提供可控响应，复现流式、故障、时序及缺字段；不替换内部 Task/Run 状态机、队列或 Sandbox 实现。发布前在 cc-la 用真实 sub2api 双协议和 SearXNG 走通同一流程。

好测试以用户行为和资源后置条件为断言，允许内部重构。检查公开 API、浏览器表现、留存成果和实际沙箱存在性；避免以调用某个内部函数或某张表的私有结构作为主要断言。

| 编号 | 外部行为与验收结果 |
| --- | --- |
| T01 | 匿名页面/API/实时连接/成果访问被拒；登录后可以操作，凭证不回显 |
| T02 | 模型列表加载、搜索、刷新和手填备用入口可用；401、空列表、超时分别反馈；失败刷新保留有效配置 |
| T03 | 两种协议分别从连接测试走到真实工作，验证多段流式、工具参数与结果往返、取消、错误及 usage；配置协议与实际请求一致 |
| T04 | 元信息来源优先级、人工覆盖撤销、别名显式映射、缺字段未知、缓存不可用均符合约定；参考价格不冒充实际费用 |
| T05 | 从主题及指定链接分别创建调研，SearXNG 搜索和网页正文读取产生可检查的来源；查询故障和不可读页面如实显示 |
| T06 | 执行中追加要求先显示待处理，工具完成后的下一模型步骤可见新要求；已有资料保留 |
| T07 | 提问后持久保存并释放真实沙箱与执行名额；延迟回答后重建并恢复，空回答不自动继续 |
| T08 | 两项工作排队；等待回答的工作让出名额；同一工作和系统并发限制保持有效 |
| T09 | 模型输出中、工具执行中及排队时取消；后台停止新动作，相关运行资源回收，既有结果保留 |
| T10 | 网络短暂失败有限重试，持续失败停止；模拟控制服务/Worker 中断后需手动重试，旧代次不能覆盖新结果 |
| T11 | 45 分钟/40 轮边界可通过测试时钟与可控模型响应验证；等待不计活跃时间，上限后不自行继续 |
| T12 | 报告可在线阅读和下载，来源可检查；销毁真实沙箱并重启应用后已交付文件仍可读取且校验一致 |
| T13 | 原工作追加修改生成新 Run 和新报告版本，旧版本可读；持久化失败不能伪装交付成功 |
| T14 | 页面刷新、断线和事件重复不产生重复工具卡或问题，服务端状态恢复正确 |
| T15 | Web fetch 的私网/重定向绕过被拒；专用 SearXNG 搜索仍可用；任务拿不到长期密钥、Docker 或宿主机执行权限；恶意 Markdown/HTML/附件不能在应用来源执行脚本 |
| T16 | 构建与运行依赖无 Electron 下载；无关菜单、路由、RPC 和服务端处理器均不可用；中文与键盘主要流程可用 |
| T17 | 新服务只占用已检查的独立资源；验证结束可回收测试数据，既有 cc-la 服务保持正常 |

现有验证先例为 W0 的 HTTP/WebSocket 鉴权检查、完整 Pi 子进程加 HTTP SSE 响应的离线检查、真实 OpenSandbox 创建/读写/销毁与成果校验，以及线上浏览器的流式/工具/取消/用量证据。这些可以提供探针经验，尚不构成本规格的完整应用测试。无需因使用同一主入口再为每个内部函数建立镜像测试。

## Out of Scope

- 管家委派、多角色编排、Agent 编辑器、并行执行工作。
- 代码修改闭环、第三方账号 Connection/写入审批、OpenConnector 集成。
- 交互式浏览器、noVNC、登录态接管和需要 JavaScript 渲染的网页保证。
- 自动化、定时任务、服务恢复后无人确认自动续跑。
- PDF 导出、多模态任务上传与完整多媒体处理；模型元信息仍可展示模态。
- 多套 ModelConnection、其他模型网关、订阅登录和自动协议降级。
- Tavily 或其他付费搜索服务、搜索供应商自动切换。
- 整套 Craft 产品功能、公开分享、桌面客户端、外部消息渠道。
- 缺乏可靠价格时的精确账单与金额硬封顶；保留已确认的时间、轮次及并发上限。
